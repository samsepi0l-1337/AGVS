# AGVS 콘텐츠 관리자 설계

## 목적과 범위

일반 PHP 웹호스팅에서 단일 내부 관리자가 AGVS 공개 사이트의 콘텐츠를 관리한다.
초기 범위는 다음 세 영역으로 한정한다.

- AGV 영상의 등록, 수정, 삭제 및 설명·참조 링크 관리
- 제품 카테고리, 제품, 모델, 사양, 이미지의 등록, 수정, 삭제
- 자료실 콘텐츠와 PDF·Excel 첨부파일의 등록, 수정, 삭제

방문 통계, 문의 관리, 다중 관리자 계정과 권한 체계, 승인 워크플로는 이번 범위에
포함하지 않는다.

## 기술 방향

기존 PHP와 JSON 기반 사이트 구조를 유지한다. 관리자는 JSON 파일과 업로드 파일을
저장하며, 공개 PHP 페이지는 이를 읽어 변경사항을 즉시 표시한다. MySQL이나 외부
CMS는 사용하지 않는다.

콘텐츠 저장은 다음 원칙을 따른다.

- KR, EN, JP 텍스트는 언어별 JSON 파일에 저장한다.
- 이미지, 동영상, 첨부파일은 언어와 무관하게 하나의 업로드 파일을 재사용한다.
- 자료실 데이터는 UI 문구 JSON과 분리해 `archivesKR.json`, `archivesEN.json`,
  `archivesJP.json`으로 관리한다.
- JSON은 임시 파일에 완전히 기록하고 유효성을 검증한 뒤 원자적으로 교체한다.
- 저장 전에 이전 JSON과 삭제 대상 파일을 백업 또는 휴지통에 보관한다.
- 저장 작업에는 파일 잠금을 적용해 손상과 충돌을 방지한다.

정적 빌드본을 함께 배포하는 환경에서는, 콘텐츠 저장 뒤 관리자에게 정적 빌드를
실행하는 게시 동작을 제공한다. PHP로 제공되는 공개 페이지는 저장 직후 변경사항을
표시한다.

## 접근 제어와 안전장치

- `/admin/login.php`에서 단일 관리자 로그인과 로그아웃을 제공한다.
- 비밀번호는 평문이 아닌 안전한 해시로 보관한다.
- 모든 관리자 페이지와 저장·삭제 요청은 로그인 세션을 확인한다.
- 세션은 일정 미사용 시간 후 만료하며, 쿠키 보안 속성을 적용한다.
- 모든 상태 변경 요청은 CSRF 토큰을 검증한다.
- 서버 측에서 필수값, slug 중복, URL 형식, 언어별 입력 완결성을 검증한다.
- 업로드 파일은 MIME 검사, 확장자 허용 목록, 용량 제한, 충돌 없는 서버 생성
  파일명을 적용한다.
- 허용 파일은 이미지(JPG, PNG, WebP), 동영상(MP4), 문서(PDF, XLS, XLSX)다.
- 삭제는 즉시 영구 삭제하지 않고 백업/휴지통으로 이동하며, 실패하면 공개 JSON은
  이전 상태를 유지한다.
- 최소 변경 이력으로 변경 시각과 변경 대상을 기록한다.

## 관리자 화면

### 대시보드

제품, 영상, 자료실의 공개 항목 수와 각 관리 화면 바로가기를 표시한다. 운영
지표나 복잡한 분석 화면은 포함하지 않는다.

### 제품 관리

카테고리, 제품, 모델의 계층을 목록과 편집 폼으로 관리한다.

- 카테고리: 식별자, KR/EN/JP 레이블과 제목, 표시 순서
- 제품: slug, 카테고리, KR/EN/JP 제품명, 표시 순서, 게시 상태
- 모델: 식별자, KR/EN/JP 모델명과 사양 목록, 이미지 목록과 각 이미지 설명
- 이미지: 업로드, 기존 파일 선택, 순서 변경, 삭제

제품과 모델 식별자는 공개 URL과 데이터 연결에 사용되므로 생성 후 변경 시 영향
범위를 안내하고 중복을 막는다.

### 영상 관리

영상 항목은 제목, KR/EN/JP 설명, 참조 URL, 썸네일, 표시 순서, 게시 상태를
가진다. 관리자는 아래 두 형식 중 하나를 선택한다.

- YouTube: 임베드 URL 관리
- 로컬 MP4: MP4 업로드와 poster 이미지 관리

공개 영상 목록에는 게시 상태인 항목만 표시한다.

### 자료실 관리

자료 항목은 slug, KR/EN/JP 제목·요약·본문, 대표 이미지, 첨부파일 목록, 게시
상태, 표시 순서, 등록일을 가진다.

첨부파일은 PDF, XLS, XLSX를 여러 개 연결할 수 있으며 각 파일은 공개 상세
페이지에서 파일명과 다운로드 버튼으로 표시한다. 공개 자료실 목록과 상세 페이지는
언어에 맞는 자료실 JSON을 읽고, 게시 상태인 항목만 노출한다.

## 공개 페이지 연동

- 기존 제품 목록과 상세 화면은 언어별 제품 JSON을 그대로 읽되, 관리자 저장
  형식에 맞춰 갱신한다.
- 기존 영상 화면은 `videos.json`의 게시된 영상만 표시한다.
- 자료실 목록과 상세 화면은 UI JSON에 섞인 기존 항목을 언어별 자료실 JSON으로
  이전해 읽는다.
- 공개 URL은 기존 slug를 유지한다. 삭제된 공개 항목 URL은 목록으로 안전하게
  이동시킨다.
- 관리자는 저장 전 유효성 오류를 확인하고, 저장 후 공개 화면 링크로 결과를
  검토할 수 있다.

## 오류 처리

- JSON을 읽거나 검증할 수 없으면 저장을 중단하고 이전 정상 버전을 유지한다.
- 업로드 실패, 크기 초과, 허용되지 않은 파일 형식은 원인을 폼에 표시한다.
- 참조되지 않는 업로드 파일은 자동 삭제하지 않고 관리자가 확인할 수 있게
  보관한다.
- 관리자 권한이 없거나 CSRF 검증에 실패한 요청은 로그인 또는 오류 화면으로
  안전하게 처리한다.

## 검증 기준

- 제품, 카테고리, 모델, 영상, 자료실 각각의 등록·수정·삭제가 KR/EN/JP 공개
  화면에 정확히 반영된다.
- 제품 이미지, 영상 파일·썸네일, PDF/XLS/XLSX 첨부파일이 업로드되고 공개
  링크에서 정상 동작한다.
- 비로그인 사용자와 CSRF 토큰이 없는 요청은 관리자 데이터에 접근하거나 변경할 수
  없다.
- 잘못된 JSON, 중복 slug, 누락된 필수값, 허용되지 않은 업로드가 저장되지 않는다.
- 저장 중 실패해도 이전 공개 콘텐츠는 유지되며, 백업본에서 복구할 수 있다.
- 삭제 후 휴지통/백업에 대상이 남고 공개 목록에서는 제외된다.
- 정적 빌드 사용 시 게시 동작 후 언어별 정적 결과도 업데이트된다.

## 구현 전제

- 호스팅은 PHP 실행, 업로드 디렉터리 쓰기, JSON 저장을 허용해야 한다.
- 관리자 비밀번호 해시는 웹에서 직접 접근할 수 없는 설정 파일 또는 호스팅 환경
  변수에 둔다.
- 업로드와 백업 경로는 실행 스크립트 권한과 공개 노출 범위를 분리해 구성한다.
